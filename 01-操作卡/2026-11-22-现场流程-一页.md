## 一、时间轴（四段，按此走）

```
入场准备 10 分钟（不碰飞机电源）
   → 飞机上电，开始计时
   → 自主飞行 正式 20 分钟 / 最多延长 10 分钟（计时不中断）
   → 简要说明 2–3 分钟（可在准备或飞行结束时完成）
   → 记录与离场
```

**关键**：30 分钟仍未完成就结束飞行；延长时段**不另设时间扣分**，按实际完成情况评价完整性。
→ 所以**时间不是瓶颈**，稳比快重要。我们一次完整飞行约 40–60 s，30 分钟够重试十几次。

### 现场两飞策略：先飞“已经成功过的小 ∞”，再飞“大的”

11/19 实机结论很明确：

| 配置 | 结果 |
|---|---|
| **a 0.45 / laps 1 / progress / k_gate 0.30** | ✅ **飞完整 1 圈，形状正确**（已验证） |
| a 0.75 / laps 3 / progress / k_gate 0.45 | ❌ 飞 1/4 圈卡死（门控死锁） |
| a 0.75 / laps 3 / **timed** | 未起飞（雷达故障），**从未实飞** |

**为什么小的能飞、大的卡死**：曲线越大越平缓，飞机更容易"追上胡萝卜"，于是触发门控死锁。
小的 ∞（a 0.45）更紧凑，飞机一直在追、没追到，反而不卡。

所以现场策略是**先复刻已成功的组合做健康检查，再上大的**：

| 飞次 | 配置 | 目的 | 预计 |
|---|---|---|---|
| **第一飞（小 ∞）** | `a 0.45` / `laps 1` / `progress` / `k_gate 0.30` | 机器与定位是否正常（已实飞验证过） | ~30 s |
| **第二飞（大 ∞）** | `a 0.75` / `laps 3` / `timed` / `v_max 0.22` | 正式演示（**放慢求稳**） | ~62 s |
| 兜底 | 第一飞若卡住 → 接管落地 → 跳过它，直接用 `timed` 飞 1 圈 | 备选 | — |

**第一飞前改参数**（不重编译）：

```bash
cd ~/template2026_ws/src/mission/config && sed -i 's/^curve_a: [0-9.]*/curve_a: 0.45/; s/^laps: [0-9]*/laps: 1/; s/^track_mode: [a-z]*/track_mode: progress/; s/^k_gate: [0-9.]*/k_gate: 0.30/' figure8.yaml && grep -nE '^(curve_a|laps|track_mode|k_gate|ctrl_mode|yaw_mode)' figure8.yaml
```

pane 2 应显示 **`弧长 L : 2.7361 m`**。

**第一飞成功后，改第二飞参数**：

```bash
cd ~/template2026_ws/src/mission/config && sed -i 's/^curve_a: [0-9.]*/curve_a: 0.75/; s/^laps: [0-9]*/laps: 3/; s/^track_mode: [a-z]*/track_mode: timed/; s/^v_max: [0-9.]*/v_max: 0.22/; s/^v_min: [0-9.]*/v_min: 0.18/' figure8.yaml && grep -nE '^(curve_a|laps|track_mode|v_max|v_min)' figure8.yaml
```

pane 2 应显示 **`弧长 L : 4.5605 m`**、`v_max/v_min : 0.22 / 0.18`，3 圈约 62 秒。

> 0.22 m/s 是刻意放慢：稳态滞后 ≈ v/K_P ≈ 0.31 m（0.32 时是 0.45 m），切角更小、更容易接管。

> 现场要传 **`06-备份/2026-11-22-fig8-现场定稿包.tgz`**（timed + a0.75 + v_max 0.22 + 门控停滞释放）。

## 四、要重飞怎么办（别重启飞控链路）

落地 disarm 之后：

1. pane 2 按 `Ctrl+C` 停任务节点；
2. 按 `↑` 回车（同一条 `roslaunch mission figure8.launch` 再起一次）；
3. 输 `1` → 拨 SwD → 再飞。

**不要** `tmux kill-session` 重起整个 `figure8.sh` —— 那会把 `fly_demo`（飞控/定位/雷达）一起重启，多花 20–30 s 还可能失败。

## 五、异常处置（照这个决策，别临场想）

| 现象 | 处理 | 谁先动 |
|---|---|---|
| 轨迹明显跑偏 / 飞机打摆 / 有人靠近 | **拨 SwD 接管**（合理接管**不扣分**），飞手接管后稳住再决定落不落 | 飞手 |
| 日志出现 `!! 横向偏差超限 ... 已转悬停` | 程序已在原地悬停等人接管；不要等它自己恢复 | 飞手 + 操作员 |
| pane 1 报 device / 时间同步错误 | **不要输 1**，找现场负责人 | 操作员 |
| 一直 `Waiting for OFFBOARD mode` | 没拨 SwD / 档位映射不对 | 飞手 |
| 地面站无响应 / SSH 断 | 飞手按接管处置，操作员重连 | 飞手 |
| 接近 30 分钟仍没飞成 | 直接报"未完成"，走补考流程，别赌 | 组长 |
