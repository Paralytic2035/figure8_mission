# 官方 square 程序原理

> 源码：`src/mission/src/square.cpp`（244 行，sha256 `7ac98a6e…`）
> 来源：`hus-king/template2026_ws` main 分支；与官方快照（sha256 `d59ddbd3…`）**仅换行符差异**，内容一致。
> 依赖：`template` 包（`template.h`）、`mavros_msgs`。可执行名 `square`，节点名却是 `template`（L44，复制遗留）。

---

## 0. 一句话

**square.cpp 不控制飞机，它只是"调度器"**：按 20 Hz 往 MAVROS 推位置目标（x, y, z, yaw），用 `mission_pos_cruise()` 判断"到没到点"，按 `mission_num` 状态机依次推进——起飞 → 4 个航点 → 降落。姿态/位置闭环全部在 PX4 的 OFFBOARD 里完成。

---

## 1. 它在系统里的位置

```
square 节点 ──20 Hz──> /mavros/setpoint_raw/local ──> MAVROS ──Mavlink──> PX4 OFFBOARD ──> 电机
   ↑ 订阅 /mavros/state（连接 / 解锁 / 模式）
   ↑ 订阅 /mavros/local_position/odom（位置 + 姿态）
   └ 服务 /mavros/set_mode（切 OFFBOARD）、/mavros/cmd/arming（解锁）
```

职责边界：

| 层 | 谁负责 | 做什么 |
|---|---|---|
| 驱动 + 定位 | `fly_demo/utils.launch`（机载 `uav_ws`） | mavros、Livox、FAST-LIO、`mid360_px4` 喂 EKF |
| 底层控制 | PX4 OFFBOARD | 位置环 → 速度环 → 姿态环 → 电机 |
| 任务层 | **square.cpp** | 目标点、时序、状态机、到点判定 |

## 2. 参数（L4–L7、L64–L72）

| 参数 | 默认 | 含义 |
|---|---|---|
| `err_max` | 0.2 | 到点误差阈值 [m] |
| `if_debug` | 0 | 1 = 程序自动切 OFFBOARD（仿真）；0 = 等飞手拨 SwD（实机） |
| `altitude` | 1.4 | 相对起飞原点的飞行高度 [m] |
| `waypoints/0..3` | (0,0)(1,0)(1,1)(0,1) | 四个航点，相对起飞原点 [m] |

来自 `config/square.yaml`；改 yaml **不用重编译**。

## 3. 启动时序（L118–161）

```
等 MAVROS connected（L84–88）
   ↓
预起飞循环（20 Hz，每轮都发 setpoint）:
   ├─ 每 3 s：未进 OFFBOARD → 尝试切（if_debug=1）／打印等待（if_debug=0）   L120–134
   ├─ 切成功后每 3 s：请求 arm                                                  L135–145
   └─ |z − altitude| < 0.2 且距上次请求 > 1 s → mission_num = 1，break         L146–155
       mission_pos_cruise(0,0,altitude,0,err_max) + publish + spinOnce + sleep  L157–160
```

两个细节：

- **预推流**：进 OFFBOARD 之前就必须有稳定的 setpoint 流，所以这一阶段已经在持续发 (0,0,altitude)。L91–105 那段被注释掉的"先发 100 帧"是等价的老写法。
- **起飞判据粗糙**：L147 用**绝对 z** 判断，没有减起飞原点；因为原地起飞时原点 z 接近 0，实际可用，但不严谨。

## 4. 任务状态机（L164–241）

```
case 1  起飞到 (0,0,altitude)
        到点后 lib_time_record_func(1.0) 再等 1 s → case 2
        若 3 s 仍未到点，强制 → case 2（容错，防止卡死）          L171–186
case 2  航点 0 (0,0)  → case 3                                   L189–195
case 3  航点 1 (1,0)  → case 4                                   L198–204
case 4  航点 2 (1,1)  → case 5                                   L207–213
case 5  航点 3 (0,1)  → case 6                                   L216–222
case 6  precision_land() → mission_num = -1 → exit(0)            L225–231
```

每轮循环末尾（L233–235）都 `publish + spinOnce + rate.sleep()`——**任何 case 卡住都不会断流**。这是任务层最重要的纪律：OFFBOARD 里 setpoint 断 500 ms 就掉模式。

## 5. 三个底层机制（都在 template.h 里）

### 5.1 `mission_pos_cruise(x, y, z, yaw, err_max)` —— 发目标

```cpp
setpoint_raw.type_mask = 8 + 16 + 32 + 64 + 128 + 256 + 512 + 2048;
setpoint_raw.coordinate_frame = 1;              // FRAME_LOCAL_NED（数值按 ENU 给，mavros 转 NED）
setpoint_raw.position = 目标 + 起飞原点;
setpoint_raw.yaw = target_yaw;                   // 弧度
```

- **type_mask 是屏蔽位**：置 1 表示该字段忽略。这里屏蔽了加速度、FORCE、yaw_rate，只让 **位置 xyz + yaw** 生效——所以是纯位置控制。
- **到点判据**：`|Δx|、|Δy|、|Δz| 都 < err_max` 且 `|Δyaw| < 0.1 rad`，满足即返回 true。

### 5.2 起飞原点（`local_pos_cb`）

第一次收到 **z ≠ 0** 的里程计时，把当时位姿锁成原点 `(x, y, z, yaw)`。之后所有目标都是**相对量**：

> `altitude = 0.8` 意思是"离起飞点 0.8 m"，不是绝对高度。

### 5.3 `precision_land()` —— 降落

1. 第一次调用锁住当前 x / y；
2. z 目标压到 **−0.15**（硬压地面）；
3. 保持 **5 s** 后返回 true；
4. 程序 `exit(0)`，**不 disarm**——落地后还要遥控器上锁。

## 6. 正方形几何

航点（L15–20，相对起飞点，单位 m）：

```
(0,1) ●───────● (1,1)
      │       │
      │       │
(0,0) ●───────● (1,0)
      ↑起飞点
```

ENU 下 x 朝东、y 朝北：**先向东 1 m → 向北 1 m → 向西 1 m**，停在起飞点正北 1 m，不回原点，原地降落。

## 7. 两个"为什么"

| 问题 | 答案 |
|---|---|
| 为什么 20 Hz？ | PX4 对 OFFBOARD 有硬性要求：setpoint 流必须 ≥ 2 Hz（500 ms 心跳超时），否则拒绝进入或直接掉模式。20 Hz 留了 10 倍余量。 |
| 为什么先发 setpoint 再切模式？ | PX4 的逻辑是"看到稳定 setpoint 流才允许 OFFBOARD"。顺序反了会被拒。所以是边发边等服务调用成功。 |

## 8. 已知的坑与局限

| # | 现象 | 说明 |
|---|---|---|
| 1 | 只飞 4 个点 | `waypoints[4]` 写死；yaml 配第 5 个点不会被读 |
| 2 | 落点不回原点 | 飞完 (0,1) 直接降落 |
| 3 | 节点名是 `template` | L44；`rosnode list` 显示 `/template`，排障易困惑 |
| 4 | 日志刷屏 | L166 每 50 ms 打一次 `mission_WARN`；`mission_pos_cruise` 内部也每轮打印 |
| 5 | 起飞判据粗糙 | L147 用绝对 z，没减原点 |
| 6 | 降落不 disarm | `Precision landing complete` ≠ 真落地，桨可能还在转 |
| 7 | 无用变量 | L57 `ctrl_pwm_client` 声明未使用 |

## 9. 答辩要点（常问 6 题）

| 问题 | 一句话答案 |
|---|---|
| 正方形怎么保证是正方形？ | 4 个航点按 (0,0)→(1,0)→(1,1)→(0,1) 顺序飞，边长由 yaml 决定，靠 `err_max` 判到点 |
| 到点判定条件？ | x/y/z 三轴误差 < `err_max` 且 yaw 差 < 0.1 rad |
| 为什么 20 Hz？ | OFFBOARD 要求 ≥2 Hz 心跳，留 10 倍余量 |
| 为什么用 `setpoint_raw` 不用 `setpoint_position`？ | 能同时控制位置/速度/yaw，且能精细屏蔽字段 |
| 降落为什么用 `precision_land()`？ | 锁 xy、压 z=−0.15、保持 5 s，比直接发 z=0 稳；但不自动上锁 |
| 怎么从仿真切实机？ | 改 yaml（`if_debug: 0`、航点）+ 换启动脚本，代码不用动 |

## 10. 与自写版的差异（答辩对照用）

| | 官方 | 自写版 |
|---|---|---|
| 航点数量 | 固定 4 个 | 按 yaml 读，配几个飞几个 |
| yaml 配 5 点 | 只飞前 4 个 | 5 个全飞 |
| 落点 | (0,1)，不回原点 | 飞回 (0,0) |
| 控制结构 | `mission_num` 状态机 | 阶段式 while，可读性更好 |
| 起飞后 | 无悬停 | 多 2 s 悬停稳姿态 |
| 日志 | 每 50 ms 刷屏 | 逐航点"飞向/到达" |
| 额外参数 | 无 | `stop_time` 每点停留 |
| 节点名 | `template` | `square` |
